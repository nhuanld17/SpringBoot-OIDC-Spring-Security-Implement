# Luồng gọi Google Calendar API — Dùng Access Token

Sau khi đã có `access_token` trong session (doc #3), bước này dùng nó để gọi **resource server** — Google Calendar API — lấy danh sách lịch và các sự kiện sắp tới.

Endpoint phụ trách: `GET /calendars` và `GET /events` trong `CalendarController`; phần gọi HTTP nằm ở `GoogleCalendarService`.

---

## Khái niệm: access token là "giấy phép"

Trong OAuth2 có 3 vai trò:

```
   Client (app này)  ──── xuất trình access token ────▶  Resource Server (Google Calendar API)
        ▲                                                        │
        │                                                        │ kiểm token: hợp lệ? còn hạn? đúng scope?
        └──────── access token do Authorization Server cấp ──────┘
                         (doc #2, #3)
```

- **Access token** = tấm giấy phép ngắn hạn, chứng minh "người dùng đã uỷ quyền cho client truy cập tài nguyên Y".
- Client đính token vào **header** `Authorization: Bearer <token>` mỗi lần gọi API.
- Resource server không cần biết mật khẩu Google của người dùng — nó chỉ kiểm token.

## Toàn cảnh sơ đồ

```
Browser ──GET /calendars──▶ CalendarController.calendars()
                                   │
   1. accessToken = tokenService.getValidAccessToken(session)   (tự refresh nếu hết hạn - doc #5)
        └── null? -> redirect "/"
                                   │
   2. calendarService.listCalendars(accessToken)
        │
        │   GET https://www.googleapis.com/calendar/v3/users/me/calendarList
        │   Header: Authorization: Bearer ya29....
        ▼
      Google Calendar API ──JSON {items:[...]}──▶ CalendarListResponse
                                   │
   3. model.addAttribute("calendars", ...) -> calendars.html
```

Với `/events` cũng tương tự, chỉ khác URL có `{calendarId}` + các query param lọc thời gian.

## Chi tiết từng bước (kèm code trong dự án)

### Bước 1 — Lấy access token còn hạn từ session

```java
// CalendarController.calendars()
String accessToken = tokenService.getValidAccessToken(session);

if (accessToken == null) {
    return "redirect:/";   // chưa uỷ quyền -> về trang chủ
}
```

`getValidAccessToken` chịu trách nhiệm trả về một access token **chắc chắn còn hạn** — nếu sắp hết hạn nó tự refresh. Chi tiết cơ chế này ở **doc #5**. Ở đây chỉ cần biết: gọi hàm này ra là có token dùng được (hoặc `null` nếu chưa uỷ quyền).

### Bước 2 — Gọi API danh sách lịch (đính `Bearer` header)

```java
// GoogleCalendarService.listCalendars()
public CalendarListResponse listCalendars(String accessToken) {
    return restClient.get()
            .uri("https://www.googleapis.com/calendar/v3/users/me/calendarList")
            .header(HttpHeaders.AUTHORIZATION, "Bearer " + accessToken)  // <-- xuất trình token
            .retrieve()
            .body(CalendarListResponse.class);
}
```

Điểm mấu chốt là dòng header:

```
Authorization: Bearer ya29.a0AfB_...
               └──┬──┘ └──────┬──────┘
             loại token    access token
             (phải có dấu cách sau "Bearer")
```

> ⚠️ Sai lầm hay gặp: viết `"Bearer" + accessToken` (thiếu dấu cách) → header thành `Bearerya29...` → Google trả **401 Invalid Credentials**. Phải là `"Bearer " + accessToken`.

JSON trả về map vào record:

```java
public record CalendarListResponse(List<CalendarItem> items) {
    public record CalendarItem(
            String id,       // vd: "primary", "abc@group.calendar.google.com"
            String summary,  // tên lịch
            boolean primary  // có phải lịch chính không
    ) {}
}
```

### Bước 3 — Gọi API sự kiện của một lịch

```java
// CalendarController.events()
@GetMapping("/events")
public String events(@RequestParam String calendarId, HttpSession session, Model model) {
    String accessToken = tokenService.getValidAccessToken(session);
    if (accessToken == null) return "redirect:/";

    String now = Instant.now().toString();  // timeMin dạng RFC3339 UTC (kết thúc bằng 'Z')

    EventsResponse events;
    try {
        events = calendarService.listUpcomingEvents(accessToken, calendarId, now);
    } catch (RestClientResponseException ex) {
        model.addAttribute("error", "Google Calendar API trả về lỗi "
                + ex.getStatusCode().value() + " khi lấy sự kiện của lịch: " + calendarId);
        return "error-page";
    }

    model.addAttribute("calendarId", calendarId);
    model.addAttribute("events", events.items());
    return "events";
}
```

Phần build URL + gọi API:

```java
// GoogleCalendarService.listUpcomingEvents()
public EventsResponse listUpcomingEvents(String accessToken, String calendarId, String timeMin) {
    URI uri = UriComponentsBuilder
            .fromUriString("https://www.googleapis.com")
            .pathSegment("calendar", "v3", "calendars", calendarId, "events") // {calendarId} là 1 segment
            .queryParam("maxResults", 10)
            .queryParam("orderBy", "startTime")
            .queryParam("singleEvents", true)
            .queryParam("timeMin", timeMin)
            .build()
            .encode()      // encode từng segment: '#'->%23, '@'->%40
            .toUri();

    return restClient.get()
            .uri(uri)
            .header(HttpHeaders.AUTHORIZATION, "Bearer " + accessToken)
            .retrieve()
            .body(EventsResponse.class);
}
```

Ý nghĩa các query param:

| Param | Vai trò |
|-------|---------|
| `maxResults=10` | Giới hạn tối đa 10 sự kiện |
| `singleEvents=true` | Tách các sự kiện lặp (recurring) thành từng lần riêng lẻ |
| `orderBy=startTime` | Sắp xếp theo thời gian bắt đầu (chỉ dùng được khi `singleEvents=true`) |
| `timeMin` | Chỉ lấy sự kiện **từ thời điểm này trở đi** (mốc "sắp tới") |

## Hai cạm bẫy encode ở bước này (đều gặp khi làm dự án)

### 1. `calendarId` chứa ký tự đặc biệt → phải encode

Nhiều `calendarId` chứa `@` và `#`, ví dụ:

```
en.vietnamese#holiday@group.v.calendar.google.com
```

`#` là ký tự bắt đầu *fragment* trong URL, `@` cũng là ký tự đặc biệt. Nếu nhét thẳng vào path mà không encode → Google **404 Not Found** (không tìm ra lịch).

Cách xử lý trong dự án: dùng `pathSegment(...)` để `calendarId` là **một segment độc lập**, rồi `.encode()`:

```
pathSegment(..., calendarId, ...) + .encode()
   -> en.vietnamese%23holiday%40group.v.calendar.google.com
        (# -> %23,  @ -> %40)  ✅ đúng dạng Google cần
```

### 2. `timeMin` phải là UTC (kết thúc `Z`), tránh dấu `+`

```java
String now = Instant.now().toString();   // 2026-07-08T15:02:35.941Z   (UTC, có 'Z')
```

Nếu dùng `OffsetDateTime.now().toString()` sẽ ra `...+07:00`. Dấu `+` trong query bị hiểu là **dấu cách** (encode không đụng `+`) → Google nhận sai định dạng thời gian → **400 Bad Request**. Dùng `Instant` (UTC, hậu tố `Z`) né được lỗi này.

## JSON sự kiện → record

```java
public record EventsResponse(List<Event> items) {
    public record Event(
            String summary,       // tiêu đề sự kiện
            EventDateTime start,
            EventDateTime end
    ) {}

    public record EventDateTime(String dateTime, String date) {
        // Google trả 'dateTime' (có giờ) HOẶC 'date' (sự kiện cả ngày)
        public String display() {
            return dateTime != null ? dateTime : date;
        }
    }
}
```

`EventDateTime` có 2 trường vì Google trả `dateTime` cho sự kiện có giờ cụ thể, `date` cho sự kiện cả ngày (all-day). Hàm `display()` chọn cái nào không null.

---

## Access token hết hạn thì sao? (401)

Access token chỉ sống ~1 giờ. Nếu gọi API bằng token hết hạn → Google trả **401**. Trong dự án, `getValidAccessToken` đã **chủ động refresh trước** khi token sắp hết hạn (còn < 60s), nên phần lớn trường hợp không bao giờ chạm tới 401. Cơ chế refresh chi tiết ở **doc #5**.

Nếu vì lý do nào đó vẫn lỗi (token bị thu hồi, mất mạng...), `try/catch RestClientResponseException` sẽ đưa người dùng sang `error-page` thay vì để văng 500.

## Ai giữ gì / dữ liệu đi đâu

```
   SESSION giữ access token
        │  getValidAccessToken()
        ▼
   CalendarController ──"Bearer <token>"──▶ Google Calendar API (resource server)
        ▲                                          │
        │            JSON (items[...])             │
        └──────────── map vào record ◀─────────────┘
        │
        ▼
   Model -> Thymeleaf (calendars.html / events.html) -> HTML trả về browser
```

Trình duyệt **không bao giờ thấy access token** — nó chỉ nhận HTML đã render sẵn. Token luôn ở phía server.

---

## Tóm tắt

1. Lấy access token còn hạn từ session qua `getValidAccessToken` (tự refresh nếu cần — doc #5).
2. Gọi Google Calendar API, đính token vào header `Authorization: Bearer <token>` (nhớ dấu cách).
3. `/calendars` gọi `calendarList`; `/events` gọi `calendars/{calendarId}/events` với query lọc thời gian.
4. Chú ý encode `calendarId` (có `#`, `@`) và dùng `Instant` UTC cho `timeMin`.
5. Kết quả JSON map vào record → đẩy ra Thymeleaf. Access token không bao giờ rời server.
